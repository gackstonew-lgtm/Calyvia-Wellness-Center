## 1. Audit Methodology & Classification Definitions

In strict accordance with the project rules, no feature has been assumed missing without code and runtime inspection:
- **Implemented & Verified:** Working code with verified runtime behavior, automated tests, or live API/UI execution.
- **Partially Implemented:** Functional code/endpoints/UI present but incomplete (e.g. mock stubs, missing end-to-end wiring, or unrouted pages).
- **Defective / Unsafe:** Implemented but presents clinical safety risks, data corruption potential, or security vulnerabilities (e.g., bypasses, hardcoded fallbacks).
- **Missing:** Zero implementation in both API and frontend.
- **Unverified:** Code exists but lacks execution proof or environment dependencies prevent verification.

## 3. High-Risk Findings & Immediate Concerns

1. **Database Fallback Mode:** In local development without a running PostgreSQL daemon, the API currently falls back to in-memory/static fixtures. This is helpful for early UI inspection, but **must never exist in staging or production**.
2. **Payment Callback Idempotency:** The M-Pesa callback receiver (`IntegrationsService.handleMpesaCallback`) must enforce database-level unique constraints on `CheckoutRequestID` and `MpesaReceiptNumber` inside a strict database transaction to prevent replay attacks or double-crediting.
3. **Clinical Field Encryption vs PostgREST/Supabase RLS:** In the current NestJS architecture, field encryption occurs in Node.js via `CryptoService`. Moving to Supabase-native PostgREST requires careful handling: either PostgreSQL `pgcrypto` functions or retaining application-layer encryption in Edge Functions / Next.js Server Components.
4. **Portal UI Routing:** The current Next.js admin frontend is housed primarily in `apps/admin/src/app/page.tsx` with client-side state switching (`activeModule`). To support deep linking, bookmarks, breadcrumbs, and role-based route guards at `portal.calyviawellness.co.ke`, it must be converted to proper Next.js App Router subroutes (`/patients`, `/crm`, `/clinical`, `/detox`, `/billing`, etc.).
